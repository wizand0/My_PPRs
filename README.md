# Генератор годового графика ППР — v4

## Назначение

`generate_ppr_schedule_global_v4.py` — Python-скрипт для автоматического формирования годового графика планово-предупредительных ремонтов (ППР) в Excel-файле.

Скрипт предназначен для исходного файла `ППР_2027.xlsx` (или аналогичного файла с той же структурой) и автоматически распределяет по календарю:

- ТО-1;
- ТО-2;
- ТО-3;
- ТО-4.

Основная задача v4 — не просто заполнить свободные недели, а построить **глобальный годовой график**, в котором работы разных разделов учитываются одновременно.

Скрипт старается:

1. соблюдать технические ограничения для каждого раздела;
2. равномерно распределять специальные ТО по месяцам;
3. не концентрировать все сложные ТО в середине года;
4. распределять работы по неделям с учетом уже существующей нагрузки;
5. не допускать конфликтов специальных ТО внутри одного раздела;
6. сохранять исходные технические настройки книги;
7. проверять результат после генерации.

# 3. Запуск

Самый простой вариант:

```powershell
python generate_ppr_schedule_global_v4.py ППР_2027.xlsx
```

После запуска скрипт:

1. открывает `ППР_2027.xlsx`;
2. анализирует лист `ППР`;
3. определяет строку недель;
4. определяет недельные столбцы;
5. определяет технические столбцы;
6. находит разделы;
7. считывает технические ограничения;
8. строит общий календарь;
9. заполняет недели;
10. выполняет проверки;
11. сохраняет Excel-файл.

В конце появляется сообщение:

```text
Сохранено: ППР_2027.xlsx
```

# 4. Структура исходного Excel

Скрипт рассчитан на текущую структуру листа `ППР`.

В используемом файле:

- строка 4 содержит номера недель;
- недельные данные находятся в диапазоне `D:BL`;
- технические настройки находятся в диапазоне `BM:BX`.

Схематично:

```text
A       B                         C        D ... BL       BM ... BX
│       │                         │        │               │
│       Раздел                    │        недели          технические
│                                 │                        настройки
```

### Защищенные области

Скрипт специально контролирует две группы столбцов:

```text
A:C
BM:BX
```

Столбцы `A:C` не должны перезаписываться генератором.

Технические столбцы `BM:BX` используются как настройки и также не должны изменяться.

После генерации скрипт проверяет, что эти области остались без изменений.

---

# 5. Технические настройки разделов

В текущем файле технические параметры находятся в `BM:BX`.

Их смысл:

| Столбец | Параметр |
|---|---|
| BM | начало сезона |
| BN | конец сезона |
| BO | количество ТО-2 |
| BP | количество ТО-3 |
| BQ | количество ТО-4 |
| BR | начало предпочтительного окна ТО-2 |
| BS | конец предпочтительного окна ТО-2 |
| BT | начало окна ТО-3 |
| BU | конец окна ТО-3 |
| BV | начало окна ТО-4 |
| BW | конец окна ТО-4 |
| BX | признак фиксации раздела |

Значения определяются непосредственно из Excel.

Например:

```text
Сезон: 2-50
ТО-2 × 2
ТО-3 × 1
ТО-4 × 1
ТО-3: 12-18
ТО-4: 33-39
```

означает, что раздел работает с 2-й по 50-ю неделю, для него предусмотрено два ТО-2, одно ТО-3 и одно ТО-4, а для ТО-3 и ТО-4 заданы соответствующие технические окна.

---

# 6. Правила периодичности

В качестве стандартных значений используются:

```text
ТО-2 × 2 в год
ТО-3 × 1 в год
ТО-4 × 1 в год
```

Но если для конкретного раздела в технических столбцах указано другое количество, используется именно оно.

Например:

```text
ТО-2 × 0
ТО-3 × 0
ТО-4 × 1
```

означает, что для данного раздела генерируется только одно ТО-4.

---

# 7. Взаимосвязь ТО

В текущей логике учитывается иерархия обслуживания:

- ТО-4 — наиболее сложное;
- ТО-3 — более сложное, чем ТО-2;
- ТО-2 — более сложное, чем ТО-1;
- ТО-1 — стандартное периодическое обслуживание.

Для годового графика используются заданные технические количества.

В частности, для стандартных разделов используется:

```text
ТО-2 × 2
ТО-3 × 1
ТО-4 × 1
```

---

# 8. Главное отличие v4 — глобальное планирование

Предыдущие версии в основном планировали каждый раздел отдельно.

Это приводило к ситуации, когда несколько разделов одновременно выбирали одну и ту же неделю или один и тот же период года.

Например:

```text
Февраль:
ТО-1
ТО-1
ТО-1
ТО-1
ТО-1
...
```

или:

```text
Март:
ТО-4
ТО-4
ТО-4
ТО-4
```

v4 сначала формирует **общий календарь**, а затем распределяет в него работы.

Поэтому при выборе недели учитывается нагрузка других разделов.

---

# 9. Месячные квоты

Ключевое изменение v4 — введены ориентиры по количеству специальных ТО в каждом месяце.

Под специальными ТО понимаются:

```text
ТО-2
ТО-3
ТО-4
```

Цель алгоритма — распределять их по всему году, а не концентрировать в середине года.

Например, итоговый график может выглядеть примерно так:

```text
Январь     4
Февраль    4
Март       4
Апрель     4
Май        4
Июнь       5
Июль       4
Август     4
Сентябрь   4
Октябрь    5
Ноябрь     4
Декабрь    4
```

Это **не жесткое требование для каждого месяца**.

Если техническое окно не позволяет выполнить работу в нужном месяце, алгоритм отступает от квоты.

Главная задача — получить сбалансированный годовой календарь.

---

# 10. Технические окна имеют приоритет

Если для раздела задано техническое окно, оно учитывается при планировании.

Например:

```text
ТО-3: 12-18
```

означает, что ТО-3 должно попасть в этот диапазон.

А если:

```text
ТО-4: 33-39
```

то ТО-4 должно попасть в недели 33–39.

Поэтому алгоритм не может произвольно перенести такую работу в январь только ради красивого распределения.

В результате возможны ситуации, когда технически ограниченные системы концентрируются в определенном периоде года.

Для разделов с широким или отсутствующим специальным окном алгоритм получает больше свободы и использует их для выравнивания общего графика.

---

# 11. Распределение по неделям

После выбора подходящего периода алгоритм выбирает конкретную неделю.

При этом учитывается:

- текущая недельная нагрузка;
- месячная нагрузка;
- наличие других специальных ТО;
- техническое окно;
- сезон работы раздела;
- недопустимость конфликтов внутри раздела.

Таким образом, алгоритм старается избежать ситуации:

```text
Неделя 20: 8 работ
Неделя 21: 0 работ
Неделя 22: 7 работ
```

и приблизить график к более равномерной загрузке.

---

# 12. ТО-1

ТО-1 заполняет остальные рабочие недели раздела.

Для него также учитывается глобальная загрузка недель.

Это важно, поскольку без глобальной балансировки все разделы могли выбрать одну и ту же неделю месяца.

Например, старая проблема:

```text
Раздел 1  → неделя 2
Раздел 2  → неделя 2
Раздел 3  → неделя 2
Раздел 4  → неделя 2
...
```

В v4 такие совпадения стараются распределять по другим свободным неделям.

При этом специальное ТО занимает неделю данного раздела вместо ТО-1.

---

# 13. Зафиксированные разделы

Столбец `BX` используется для фиксации раздела.

Если раздел помечен как зафиксированный, его существующий график не должен перегенерироваться.

В логе это отражается примерно так:

```text
Разделов: 15; зафиксировано: 2; генерируется: 13
```

Это позволяет повторно запускать генератор, не затрагивая уже вручную утвержденные разделы.

---

# 14. Лог работы

Скрипт специально выводит подробную информацию.

Например:

```text
[01/15] Приступаю к разделу «Электрощитовое оборудование (этажные)»

Сезон: 2-50; ТО-2×2, ТО-3×1, ТО-4×1

Добавлено: ТО-1×8, ТО-2×2, ТО-3×1, ТО-4×1

ТО-2: недели 3, 7
ТО-3: недели 49
ТО-4: недели 12

Готово.
```

Это позволяет быстро проверить, что произошло с каждым разделом.

# 15. Итоговый отчет

В конце скрипт выводит сводку:

```text
Обработано разделов: 15
ТО-1: 120
ТО-2: 23
ТО-3: 12
ТО-4: 15
```

Также выводятся распределения:

```text
Распределение ТО-3:
4:1, 13:1, 15:1, ...

Распределение ТО-4:
3:1, 7:1, 8:1, ...
```

И отдельно:

```text
Месячное распределение крупных ТО (ТО-2/3/4):
янв:4, фев:4, мар:4, ...
```

и:

```text
Месячное распределение ТО-1:
янв:9, фев:9, мар:9, ...
```

Это один из основных способов визуально проверить качество построенного календаря.

---

# 16. Проверки

После генерации выполняются проверки.

Проверяется, в частности:

### Защищенные столбцы

Не изменились ли:

```text
A:C
BM:BX
```

### Специальные ТО

Проверяется наличие конфликтов специальных ТО внутри одного раздела.

Например:

```text
Наружная канализация:
неделя 39 → ТО-2 + ТО-4
```

будет обнаружено как конфликт.

### Сезон

Проверяется, что работы попали в допустимый сезон раздела.

### Технические окна

Проверяется соответствие ТО-3/ТО-4 заданным окнам.

### Дубликаты

Проверяется, что один и тот же раздел не получил несколько специальных ТО в одну неделю.

---

# 17. Предупреждения

Если скрипт обнаружил проблему, она выводится в конце:

```text
ПРЕДУПРЕЖДЕНИЯ (1):
 - Наружная канализация [строка 37]:
   два специальных ТО попали на одну неделю.
```

Это не следует игнорировать.

После такого сообщения необходимо проверить соответствующий раздел на листе `ППР`.

# 18. Вторая программа — fill_ppr_weeks_v2.py

Генератор и `fill_ppr_weeks_v2.py` выполняют разные задачи.

### generate_ppr_schedule_global_v4.py

Формирует **логику годового графика**:

```text
какой раздел
какое ТО
на какую неделю
```

### fill_ppr_weeks_v2.py

После этого обрабатывает сформированный ППР и переносит/заполняет недели на связанные листы Excel.

Рекомендуемый порядок:

```text
1. generate_ppr_schedule_global_v4.py
2. fill_ppr_weeks_v2.py
```

Например:

```powershell
python generate_ppr_schedule_global_v4.py ППР_2027.xlsx
python fill_ppr_weeks_v2.py ППР_2027.xlsx
```

После второго запуска необходимо проверить его отчет о конфликтах.

Если он сообщает:

```text
Конфликтов ТО-2/ТО-3/ТО-4 по неделям не найдено.
Остальное прошло без предупреждений.
```

то результат прошел дополнительные проверки `fill_ppr_weeks_v2.py`.

# 20. Важные особенности

## Скрипт не определяет технические нормы самостоятельно

Он использует параметры, находящиеся в Excel.

Если изменить технические окна в `BM:BX`, изменится и результат генерации.

Поэтому технические параметры должны быть проверены до запуска.

## Скрипт не должен изменять технические настройки

`BM:BX` являются входными параметрами.

Генератор использует их для построения графика, но не должен переписывать их.

## Не следует вручную менять недели перед повторным запуском

Если раздел не зафиксирован, повторный запуск может построить новый вариант графика.

Если необходимо сохранить конкретный раздел, его следует зафиксировать через предусмотренный механизм `BX`.

---

# 21. Что делать при изменении структуры Excel

Если в будущем изменятся:

- расположение строки недель;
- диапазон недель;
- расположение технических столбцов;
- структура разделов;
- назначение столбцов `BM:BX`;

скрипт может потребовать доработки.

Особенно важно не менять структуру технических параметров без проверки генератора.

# 24. Версия

Текущая версия:

```text
generate_ppr_schedule_global_v4.py
```

Основная идея версии v4:

> **Годовой график строится глобально: специальные ТО распределяются по всему году с учетом месячных квот, технических окон и нагрузки по неделям, а ТО-1 заполняет оставшиеся рабочие недели с дополнительной балансировкой.**

Это позволяет получить не просто заполненную таблицу, а более равномерный и контролируемый годовой график ППР.
